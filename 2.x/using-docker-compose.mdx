Install and run Zepeed using Docker Compose.

## Requirements

Install the following on your system:

<Tabs>
  <Tab title="macOS">
    - **Docker Desktop**: [Download](https://www.docker.com/products/docker-desktop)
  </Tab>
  <Tab title="Linux">
    - **Docker Engine**: [Installation guide](https://docs.docker.com/engine/install/)
    - **Docker Compose**: Included with Docker Engine 24.0\+
  </Tab>
  <Tab title="Windows">
    - **Docker Desktop**: [Download](https://www.docker.com/products/docker-desktop)
  </Tab>
</Tabs>

Verify installation:

```bash
docker --version
docker compose version
```

## Setup

<Tabs>
  <Tab title="Proxmox LXC">
    <Steps>
      <Step title="Create the container">
        1. In Proxmox, download the **Debian 12** CT template.
        2. Create a new LXC container with:
           - **RAM**: 2048 MB (4096 recommended)
           - **Disk**: 8 GB
           - **Nesting**: enabled (required for Docker)
           - Uncheck **Unprivileged container** — Docker needs a privileged LXC.
        3. Start the container and open its shell.
      </Step>
      <Step title="Install Docker inside the LXC">
        ```bash
        apt update && apt install -y curl
        curl -fsSL https://get.docker.com | sh
        ```
      </Step>
    </Steps>

    Continue with [Common setup](#common-setup) below.
  </Tab>
  <Tab title="CasaOS">
    CasaOS ships with Docker pre-installed. Open the CasaOS terminal (via **Files → Terminal** or SSH) and continue directly with [Common setup](#common-setup).

    <Note>
      CasaOS App Store integration is not yet available for Zepeed. Use the terminal-based setup below.
    </Note>
  </Tab>
  <Tab title="Ubuntu / Debian">
    Install Docker if not already present:

    ```bash
    curl -fsSL https://get.docker.com | sh
    sudo usermod -aG docker $USER   # then log out and back in
    ```

    Continue with [Common setup](#common-setup) below.
  </Tab>
</Tabs>

## Common setup

<Steps>
  <Step title="Create a working directory">
    ```bash
    mkdir -p /opt/zepeed && cd /opt/zepeed
    ```
  </Step>
  <Step title="Download the Compose file and env template">
    ```bash
    curl -fsSL https://raw.githubusercontent.com/marjose123/zepeed/main/compose.prod.yml -o compose.prod.yml
    curl -fsSL https://raw.githubusercontent.com/marjose123/zepeed/main/.env.prod.example -o .env
    ```
  </Step>
  <Step title="Configure your environment">
    Open the `.env` file in your editor:

    ```bash
    nano .env
    ```

    **Minimum required values:**

    | Variable | Description |
    | --- | --- |
    | `APP_DOMAIN` | Your domain, e.g. `zepeed.example.com` |
    | `APP_URL` | Full URL, e.g. `https://zepeed.example.com` |
    | `APP_KEY` | Generate using the command below |
    | `ACME_EMAIL` | Email for Let's Encrypt notifications |
    | `DB_ROOT_PASSWORD` | Strong random password for MariaDB root |
    | `DB_PASSWORD` | Strong random password for the app user |
    | `PUSHER_APP_KEY` | Any random string, e.g. `zepeed_key` |
    | `PUSHER_APP_SECRET` | A different strong random string |
    | `PUSHER_APP_ID` | Any random string, e.g. `zepeed_id` |
    | `DEFAULT_ADMIN_PASSWORD` | **Required** — Admin password (minimum 8 characters) |

    **Generate `APP_KEY`:**

    ```bash
    docker run --rm marjose123/zepeed:latest php artisan key:generate --show
    ```

    Paste the output (starts with `base64:`) into `APP_KEY=`.
  </Step>
  <Step title="Pull and start">
    ```bash
    docker compose -f compose.prod.yml pull
    docker compose -f compose.prod.yml up -d
    ```

    Docker pulls all images, runs database migrations automatically, and starts the application. First boot takes ~60 seconds.

    The stack includes:

    - **Traefik** — Reverse proxy with automatic Let's Encrypt TLS
    - **Zepeed app** — The main application
    - **MariaDB 11** — Database
    - **Redis** — Cache, sessions, and queue
    - **Soketi** — WebSocket server for real-time updates
  </Step>
  <Step title="Default admin account">
    A default admin account is created automatically on first boot using the credentials in `.env`:

    | Variable | Default |
    | --- | --- |
    | `DEFAULT_ADMIN_EMAIL` | `admin@zepeed.local` |
    | `DEFAULT_ADMIN_PASSWORD` | **No default — must be set in `.env`** |

    <Warning>
      `DEFAULT_ADMIN_PASSWORD` is **required** — there is no default fallback. The container will fail to create the admin account if this value is not set.
    </Warning>

    On every subsequent restart, the account creation step is skipped automatically.
  </Step>
  <Step title="Open in browser">
    Navigate to `https://your-domain.com`. Let's Encrypt issues a certificate automatically on first request (takes ~10 seconds).
  </Step>
</Steps>

## Essential commands

```bash
# View logs
docker compose -f compose.prod.yml logs -f app

# Run artisan commands
docker compose -f compose.prod.yml exec app php artisan <command>

# Stop containers
docker compose -f compose.prod.yml down

# Rebuild after Dockerfile changes
docker compose -f compose.prod.yml up -d --build app

# Backup database
docker compose -f compose.prod.yml exec app bash /var/www/html/docker/production/backup.sh
```

## Troubleshooting

### Container fails to start

Check logs for error messages:

```bash
docker compose -f compose.prod.yml logs app
docker compose -f compose.prod.yml logs mariadb
```

Common issues:

- **Port already in use**: Change `TRAEFIK_HTTP_PORT` and `TRAEFIK_HTTPS_PORT` in `.env`
- **Insufficient disk space**: Clean up with `docker system prune`
- **Permission denied**: Ensure Docker daemon is running and you have permissions

### Database connection fails

Verify MariaDB is running and healthy:

```bash
docker compose -f compose.prod.yml ps mariadb
docker compose -f compose.prod.yml exec mariadb mariadb -u root -p -e "SELECT 1"
```

If MariaDB fails to start, check data directory permissions:

```bash
docker compose -f compose.prod.yml exec mariadb chmod 755 /var/lib/mysql
```

### Application errors after startup

Wait for MariaDB to finish initialization. The first startup takes longer:

```bash
docker compose -f compose.prod.yml logs mariadb | grep "ready for connections"
```

Then verify the app is running:

```bash
docker compose -f compose.prod.yml restart app
docker compose -f compose.prod.yml logs app
```

### Reset to clean state

<Warning>
  This will delete all data including speedtest results.
</Warning>

```bash
docker compose -f compose.prod.yml down -v
docker compose -f compose.prod.yml up -d
```
